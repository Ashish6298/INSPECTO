--------------------------------------------------------------------------------
[OBJECTIVE]
Resolve all blocking compilation errors, broken type signatures, and deprecated API
usages under Flutter 3.27+/3.29+ so `flutter analyze` passes with 0 errors.

[TARGET FILES]
- `inspecto/lib/core/theme/app_theme.dart`
- `inspecto/lib/domain/entities/api_request.dart`
- `inspecto/lib/domain/entities/api_response.dart`
- `inspecto/test/widget_test.dart`

[DETAILED SPECIFICATION]
1. `CardTheme` & `TabBarTheme` Type Fixes:
   - In `app_theme.dart` (lines 57 and 104), replace `cardTheme: CardTheme(...)` with
     `cardTheme: CardThemeData(...)`.
   - In `app_theme.dart` (lines 65 and 113), replace `tabBarTheme: TabBarTheme(...)` with
     `tabBarTheme: TabBarThemeData(...)`.
2. Color Deprecation Migration:
   - Modern Flutter deprecates `.withOpacity(...)` in favor of `.withValues(alpha: ...)`.
   - Audit all instances in `app_theme.dart`, `request_url_bar.dart`, `response_viewer.dart`,
     `request_body_editor.dart`, and `authorization_editor.dart`. Replace `.withOpacity(x)`

   - In `api_request.dart`, change `enum HttpMethod { GET, POST, PUT, DELETE, PATCH }`
     or add `// ignore: constant_identifier_names` if maintaining uppercase is needed

   - In `api_response.dart` (line 22), wrap single-line `if` statements in braces `{ ... }`.
4. Replace Default Counter Test:
   - `inspecto/test/widget_test.dart` currently contains boilerplate counter code that
     fails. Rewrite `widget_test.dart` into an actual smoke test verifying that
     `InspectoApp` initializes its root providers and renders the `SplashScreen`.

- Run `cd inspecto && flutter analyze`. Result must output: "No issues found!".
- Run `cd inspecto && flutter test`. All tests must pass with exit code 0.

already attempts to call, preventing 404/500 failures during collection and environment
management.

[TARGET FILES]

- `backend/src/controllers/collection.controller.js`
- `backend/src/routes/environment.routes.js`

[DETAILED SPECIFICATION]
1. Collection Management Endpoints:
   - Implement `POST /api/collections/:id/requests`:
     - Controller method: `addRequestToCollection(req, res)`
     - Flow: Validate collection exists -> create new `ApiRequest` document with `collectionId: req.params.id`
       -> push request ID into `Collection.requests` array -> save collection -> return 201 with created request.
   - Implement `DELETE /api/collections/:id`:
     - Controller method: `deleteCollection(req, res)`
     - Flow: Remove all associated `ApiRequest` documents -> remove `Collection` document -> return 200.
   - Implement `DELETE /api/collections/:id/requests/:requestId`:

2. Environment Management Endpoints:
   - Implement `PUT /api/environments/:id`:
     - Controller method: `updateEnv(req, res)`

   - Implement `DELETE /api/environments/:id`:
     - Controller method: `deleteEnv(req, res)`
     - Flow: Remove environment document -> return 200 `{ message: 'Environment deleted' }`.
   - Implement `PATCH /api/environments/:id/activate`:
     - Sets target environment `isActive: true` and resets all others to `false`.

[ACCEPTANCE CRITERIA]

  * `POST /api/collections/:id/requests` successfully appends a request.
  * `PUT /api/environments/:id` updates variables.
  * `DELETE /api/environments/:id` deletes the document cleanly.

PHASE 1.2: Environment Variable Schema & Execution Engine Alignment
--------------------------------------------------------------------------------
[OBJECTIVE]
Eliminate the data contract mismatch between Flutter and Node.js for Environment
variables, fix regex escaping vulnerabilities in variable resolution, and handle
multi-value response headers safely.

[TARGET FILES]
- `backend/src/models/Environment.js`
- `backend/src/services/variableResolver.service.js`
- `inspecto/lib/domain/entities/environment.dart`
- `inspecto/lib/data/repositories/environment_repository_impl.dart`
- `inspecto/lib/presentation/providers/environment_provider.dart`
- `inspecto/lib/data/datasources/api_remote_data_source.dart`

[DETAILED SPECIFICATION]
1. Data Model Alignment:
   - Standardize variables format. Define an `EnvironmentVariable` object:
     `{ key: String, value: String, enabled: Boolean }`.
   - In Dart: Create `EnvironmentVariable` entity and update `Environment` to hold
     `List<EnvironmentVariable> variables` (or provide safe bidirectional conversion
     methods between List and Map).
   - In `environment_repository_impl.dart`: Safely serialize and deserialize variables
     array without throwing type cast exceptions.
2. Safe Variable Resolution (Backend):
   - In `variableResolver.service.js`, update `resolveVariables`:
     - Check if `variables` is an Array before looping; return original string if invalid.
     - Escape regex special characters in `variable.key` so keys like `user.id` or `api[key]`
       do not break `new RegExp(...)`:
       `const escapedKey = variable.key.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');`
       `const regex = new RegExp(`{{${escapedKey}}}`, 'g');`
3. Axios Header Normalization:
   - In `api_remote_data_source.dart`, line 42:
     Axios headers can contain arrays (e.g. `set-cookie: ["a=1", "b=2"]`).
     Replace `Map<String, String>.from(data['headers'] ?? {})` with a safe mapper that
     joins array elements with `, ` or handles non-string values gracefully:
     ```dart
     Map<String, String> headers = {};
     (data['headers'] as Map<String, dynamic>?)?.forEach((k, v) {
       headers[k] = v is List ? v.join(', ') : v.toString();
     });
     ```

[ACCEPTANCE CRITERIA]
- Saving an environment with special keys (e.g. `{{auth.token}}`) resolves correctly in URLs.
- Target APIs returning multiple cookies or list headers do not cause Dart type errors.

PHASE 2.0: cURL Importer & Multi-Language Code Snippet Generator
--------------------------------------------------------------------------------
[OBJECTIVE]
Enable pasting raw cURL commands from browsers/docs into INSPECTO, and exporting any
configured request as production code snippets.

[TARGET FILES]
- `inspecto/lib/core/utils/curl_parser.dart` (NEW)

- `inspecto/lib/presentation/widgets/curl_import_dialog.dart` (NEW)

[DETAILED SPECIFICATION]
1. cURL Parser Engine:
   - Extract Method (`-X POST`, `--request GET`).
   - Extract URL (handling single and double quotes).
   - Extract Headers (`-H 'Content-Type: application/json'`).
   - Extract Data/Body (`-d`, `--data`, `--data-raw`, `--data-binary`).
   - Handle line continuations (`\`).
2. Code Snippet Generator:
   - Support target languages:
     * cURL

     * JavaScript / TypeScript (`fetch` and `axios`)

     * Go (`net/http`)

     "Copy to Clipboard" button.
3. UI Integration:
   - Add "Import cURL" button in AppBar or inside URL input row.
   - Add `</>` Code icon in AppBar next to Save button to open the snippet modal.

[ACCEPTANCE CRITERIA]
- Pasting `curl -X POST https://api.example.com/login -H "Content-Type: application/json" -d '{"user":"test"}'`
  automatically sets Method: POST, URL: https://api.example.com/login, Headers: Content-Type, Body: {"user":"test"}.
- Generated snippets execute correctly in their respective language runtimes.
